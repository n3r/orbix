**Goal:** Close out the tvOS parity rebuild. **(1)** Merge `origin/main` into `tv-ui` — the remote moved ahead by 26 commits (group profiles, subtitle pre-extraction, six new home rows, Library Categories/Browse tabs, and a **pre-rebuild-era tvOS commit** that added EN/RU localization + a Top Shelf extension) — resolve the conflicts (all in `clients/tvos`; the rebuild is authoritative), and re-green every repo + tvOS gate on the merged tree, re-running the profile/PIN DTO tests against the merged wire shapes. **(2)** Run a **full-parity audit** of every TV screen side-by-side against the web on the same NAS data, producing an audit table and dispositioning the accumulated ledger deviations (fix-now / accepted-documented / hardware-only). **(3)** **Ship to the NAS** (USER-GATED): PR `tv-ui → main`, merge on the user's go, deploy the merged `main` with production-safety rails (rollback tag, additive-ship stale-file cleanup, health + web smoke, migrations-no-op verification), then run the previously stale-NAS-blocked live checks (wishlist toggle round-trip from the TV, live-TV tokened-proxy playback from the TV, Home "Undefined" rail re-check). **(4)** **Apple TV 4K hardware pass** (USER-INTERACTIVE): sideload to the real device ("Комната развлечений", A12), walk the acceptance checklist with the user (pairing, PIN with their real pin, sim-blocked focus/OSD checks, HEVC 2160p, quality switch, live zap/failover, subtitles, language, kids). **(5)** Wrap-up: final ledger note, PR/branch hygiene, controller-owned memory update. ## Global Constraints

- **Read-only until a task says otherwise.** Tasks 2 and 4 are audits/acceptance passes: they change **no** code unless a defect is found, and then the fix lands in the owning task's file(s) with that file's gate re-run before continuing — never a drive-by edit.
- **USER-GATED / USER-INTERACTIVE checkpoints are hard stops.** The executor MUST pause and obtain explicit controller/user confirmation before **Task 3 Step 1** (the PR/merge/deploy sequence — production) and before **every physical-device step in Task 4**. Physical-device steps require the user: the Apple TV 4K powered on, on the same LAN, and possibly approving the pairing on-screen. These are **not** autonomous steps; the agent guides, the user acts.
- **Production-safety rails for the deploy (Task 3):** (a) **tag/commit a rollback image** of the running `orbix-api` container before `--build`; (b) the git-archive ship is **additive** — files deleted on `main` are NOT removed by extraction, so compute stale files as `git ls-tree` (what should exist) vs the NAS `find` (what does exist) and `rm` the difference using **`grep -Fxvf`** (fixed-string, full-line, order-independent — **NOT `comm`**, which needs sorted input and would mis-handle path ordering); (c) **never touch `/volume1` media or the named Docker volumes** (`orbix-db`/`orbix-metadata`/`orbix-transcode`/`orbix-mounts`) — media is mounted read-only, stale-file cleanup operates **only** on the shipped source-tree directory; (d) **migrations are no-op — verify, don't assume** (Task 3 checks container logs / `prisma migrate status` show no pending migration; the merged tree's only migration beyond the branch base is `20260705000000_profile_groups`, already applied on the NAS because it runs `main`); (e) health-check + web smoke before declaring success, rollback on failure.
- **PIN safety (binding, from the Phase-4 user decision):** **never ask for, embed, log, or store the user's real PIN — anywhere, including hardware-pass notes and screenshots.** On hardware (Task 4) the user enters their real PIN themselves; the agent records only "entered / accepted / rejected", never the digits, and captures no screenshot that could show the pad mid-entry with digits resolvable. All *automated* PIN verification (if any is still needed in the merged-wire re-check) uses a **throwaway profile with a throwaway PIN** (`2468`), created via the API and deleted after, with the device's original active profile restored — never Nikita's real-PIN profile, not even with a deliberately wrong PIN.
- **Tokens only ever by env-var reference.** Authenticated smokes load `.superpowers/sdd/dev-device-token.env` (`set -a; source …; set +a`) and pass `"$ORBIX_TEST_TOKEN"` by reference — never printed, echoed, or `curl -v`'d to screen. Deploy SSH credentials/keys are likewise never echoed.
- **Web is the source of truth for the audit** — and the web moved during the drift (Library tabs, six home rows, group-profile Account/Profiles UI). The audit compares the TV against **current** web on the **same NAS data**; drift-induced parity shifts are first-class audit findings, not oversights (see Task 1's drift inventory and Task 2).
- **Build/test gates (repo):** `pnpm typecheck` (full turbo) + `pnpm --filter @orbix/api lint` + `pnpm --filter @orbix/api test` + `pnpm --filter @orbix/core test` + `pnpm --filter @orbix/web test` (run lint separately per CLAUDE.md whenever `apps/api/**` is in the tree, which it is post-merge). **tvOS gates:** `cd clients/tvos && xcodegen generate`; app `build` on `platform=tvOS Simulator,name=Apple TV 4K (3rd generation)` `CODE_SIGNING_ALLOWED=NO`; `OrbixKitTests` `test`. Substitute the sim name from `xcrun simctl list devices available | grep "Apple TV"` if unavailable.
- **Commit discipline:** small commits on branch `tv-ui` (verify `git branch --show-current`); each commit leaves all gates green. The merge commit (Task 1) and any fix-commits are the only code commits expected. **Memory-file updates are a controller step, not an implementer step** (Task 5).
