# SP2 M3: The App (home rails · title pages · production player · search) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the M1 "spike list" into a genuinely usable living-room app: Netflix-style home rails, title/season/episode detail pages, a production player (resume, progress+heartbeat reporting, native audio/subtitle track selection, next-episode), and search — all driven by the SP1 server contract, with kids profiles enforced end-to-end.

**Architecture:** SwiftUI navigation (`NavigationStack`) with `.focusSection()` per rail; a bounded disk+memory image cache (fixing the M2 follow-up); the production player wraps `AVPlayerViewController` with a coordinator that owns the time observer + progress reporter and tears them down in `dismantleUIViewController`. All data via the existing `OrbixClient` (extended with the endpoints M3 needs); the server already ships everything (home rows, item/season/episode detail, similar, search, progress, stop).

**Tech Stack:** Swift 6, SwiftUI (NavigationStack, focus engine), AVKit, OrbixKit. Verified via `xcodebuild build`/`test` + live simulator smokes (screenshots) against a throwaway server with seeded, enriched-ish fixtures.

**Spec:** `docs/superpowers/specs/2026-07-03-tv-app-and-client-server-contract-design.md` §5 (M3). Consumes SP1 endpoints: `/api/home/rows`, `/api/items/:id`, `/api/items/:id/seasons/:n/episodes`, `/api/items/:id/similar`, `/api/search`, `/api/playback/info`, `/api/items/:id/progress`, `/api/playback/:id/stop`, `/api/images/*`.

## Global Constraints

- tvOS code under `clients/tvos/` only; `.xcodeproj` gitignored (`xcodegen generate`). No server changes (all endpoints shipped + smoke-proven).
- Deployment target tvOS 17; Swift 6 complete concurrency (actors for mutable state, `@MainActor` view models).
- The app uses relative `/api/...` against the configured base URL and uses `streamUrl` verbatim (token embedded). tvOS capability profile = `Capabilities.appleTV` (subtitleDelivery: "hls" so native subtitle picker is populated).
- Kids enforcement is server-side on every route — the client must not need to re-filter, but must gate UI affordances gracefully (a kids profile simply receives filtered rows/404s; surface "not available" rather than crashing).
- Build gates per task: `xcodebuild -scheme Orbix build` → BUILD SUCCEEDED; `-scheme OrbixKit test` green (readiness gate skips without env). SourceKit single-file diagnostics are false positives.
- Address the carried-over M2 follow-ups where they land: ImageLoader bounding (Task 1), PlayerViewController observer teardown (Task 3), a shared 401→re-pair handler (Task 3/6), empty-states (each view), app icon (Task 6).
- Commit after every task; each task ends with a live screenshot smoke where it has visible UI.

### Task 1: Bounded ImageLoader + PosterCard + home rails

**Files:**
- Modify: `clients/tvos/Sources/OrbixKit/ImageLoader.swift` (bound the cache — the M2 follow-up)
- Create: `clients/tvos/Sources/Orbix/Home/PosterCard.swift`
- Create: `clients/tvos/Sources/Orbix/Home/HomeView.swift`
- Modify: `clients/tvos/Sources/Orbix/RootView.swift` (route `.ready` → HomeView instead of SpikeListView)
- Modify: `clients/tvos/Sources/OrbixKit/DTOs.swift` (extend MediaCard with backdropPath, progress {positionSec,durationSec}?, resume {seasonNumber,episodeNumber,episodeTitle}? — the fields `/home/rows` sends; keep them optional)

**Interfaces:**
- `ImageLoader` memory cache → `NSCache<NSURL, NSData>` (evicts under memory pressure) with a countLimit (~200); keep the disk cache but cap its size (best-effort prune). In-flight coalescing: a dictionary of `Task<Data?, Never>` keyed by URL so concurrent misses share one fetch.
- `PosterCard`: a focusable poster (2:3) via ImageLoader with a placeholder; title + year below; a thin resume progress bar overlaid when `progress` present. `.focusable()`, scales on focus (the tvOS convention).
- `HomeView`: `@MainActor @Observable HomeModel` loads `/home/rows` → `[HomeRow]`; a vertical `ScrollView` of rails, each a `.focusSection()` horizontal `ScrollView`/`LazyHStack` of `PosterCard`s. Selecting a card navigates to the title page (Task 2 — for Task 1, a placeholder destination or print is fine; wire real nav in Task 2). Loading/empty/error states.

- [ ] **Step 1:** Extend MediaCard DTO (optional fields) + a DTO decode test for a home-rows item carrying progress/resume/backdropPath. Bound ImageLoader (NSCache + coalescing) — add/adjust a unit test if feasible (cache hit returns without a second fetch via an injected fetcher).
- [ ] **Step 2:** Implement PosterCard + HomeView + HomeModel; route `.ready` → HomeView.
- [ ] **Step 3:** `xcodebuild build` → BUILD SUCCEEDED; `-scheme OrbixKit test` green.
- [ ] **Step 4 — live smoke (controller or subagent):** throwaway server + seeded items (some with progress via a PlaybackState row) + a paired device+profile (reuse the M2 harness pattern; launch with `-orbixBaseURL -orbixToken` dev args); screenshot the home screen — confirm rails render, posters/placeholders show, focus scales a card, a resume bar appears on the in-progress item. Teardown.
- [ ] **Step 5:** Commit: `feat(tvos): bounded image cache + home rails`.

### Task 2: Title / detail page + navigation

**Files:**
- Modify: `clients/tvos/Sources/OrbixKit/OrbixClient.swift` (+ `itemDetail(id:) -> ItemDetail`, `similar(id:) -> [MediaCard]`)
- Modify: `clients/tvos/Sources/OrbixKit/DTOs.swift` (`ItemDetail`: id, kind, title, year, overview, backdropPath?, logoPath?, runtimeSec?, rating?, genres[], cast[{name,role?,...}] (top ~10), director?, seasons[{seasonNumber,name?,episodeCount?}]? (series), files[{id,...}] (movie))
- Create: `clients/tvos/Sources/Orbix/Title/TitlePage.swift`
- Modify: `clients/tvos/Sources/Orbix/Home/HomeView.swift` (NavigationStack push to TitlePage on card select)

**Interfaces:**
- `TitlePage`: full-bleed backdrop (ImageLoader) + logo/title, metadata row (year · rating · runtime · genres), overview, a focusable **Play** button (resume-aware label "Resume"/"Play"), and a "More like this" rail (`similar`). For a movie: Play uses `files[0].id`. For a series: a season strip / "Play S1E1" (episode navigation in Task 4 — Task 2 can show seasons and defer episode lists). Kids-blocked items 404 → a graceful "not available" (shouldn't be reachable from filtered rows, but handle it).
- Navigation: `HomeView` wraps content in a `NavigationStack`; `PosterCard` selection pushes `TitlePage(itemId:)`.

- [ ] Steps: DTO + client methods (+decode test) → TitlePage view → wire nav → build green → live smoke (navigate home→title, screenshot the detail page + backdrop + Play) → commit `feat(tvos): title/detail page + navigation`.

### Task 3: Production player (resume · progress+heartbeat · track selection · stop)

**Files:**
- Modify: `clients/tvos/Sources/Orbix/Player/PlayerViewController.swift` (rename/expand from the M1 wrapper) — add a Coordinator owning the periodic time observer + progress reporter; implement `dismantleUIViewController` teardown (the M2 follow-up)
- Create: `clients/tvos/Sources/Orbix/Player/PlaybackController.swift` (an actor/observable coordinating: playbackInfo → AVPlayer(url:) → seek to resume → 10s progress PUT with playSessionId → `/stop` on teardown)
- Modify: `clients/tvos/Sources/OrbixKit/OrbixClient.swift` (+ `putProgress(itemId:positionSec:durationSec:episodeId?:playSessionId?)`, `getProgress(itemId:episodeId?)`, `stopPlayback(playSessionId:)`)
- Modify: `clients/tvos/Sources/Orbix/Title/TitlePage.swift` (Play presents the production player)

**Interfaces:**
- On play: `getProgress` → resume position; `playbackInfo(fileId:, .appleTV)`; present `AVPlayerViewController` with `AVPlayer(url: streamUrl)`; on `.readyToPlay` seek to resume (if >0 and not finished); native audio/subtitle pickers come from the in-manifest renditions (no client code). Set `externalMetadata` (title) for the Info panel/Now Playing.
- Progress reporting: a periodic time observer every 10s PUTs `/api/items/:id/progress` with `{positionSec,durationSec,episodeId?,playSessionId}`; also on pause and on teardown. On teardown: `stopPlayback(playSessionId)` (sendBeacon-equivalent) + remove the time observer in `dismantleUIViewController` (no leak).
- Shared 401 handling: if any authenticated call returns 401 mid-session, route the app back to `.needsPairing` (the M2-review follow-up) via an AppModel hook.

- [ ] Steps: client methods (+tests) → PlaybackController + player rewrite with teardown → wire Play → build green → **live playback smoke** (reuse the M1 fixture harness: play a remux title, confirm it reaches playback, seek, exit → verify a progress row was written server-side and `/stop` was called; screenshot the player) → commit `feat(tvos): production player — resume, progress heartbeat, track selection, stop`.
